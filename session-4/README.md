# Session 4: Data-Driven Modernization Strategy

## Overview

Session 4 is the **capstone session** of the legacy modernization course, focusing on **strategic decision-making** through data-driven analysis. While earlier sessions teach tactical techniques (characterization tests, isolation patterns), this session teaches you to:

1. **Measure before acting** - Use automated analysis to identify where modernization effort should focus
2. **Align with business value** - Combine technical metrics with product roadmap to prioritize work
3. **Make informed decisions** - Choose refactoring strategies based on quantitative data
4. **Create actionable roadmaps** - Plan phased modernization aligned with business objectives

## Learning Objectives

By the end of this session, you will be able to:

- **Analyze legacy codebases quantitatively**:
  - Parse git history to identify change frequency patterns
  - Calculate code complexity metrics (cyclomatic complexity)
  - Identify test coverage gaps
  - Combine metrics into risk scores (hotspot detection)

- **Align modernization with business value**:
  - Map technical debt to upcoming features
  - Calculate value/effort ratios
  - Prioritize work by ROI (return on investment)
  - Create phased roadmaps that balance technical and business needs

- **Select appropriate refactoring strategies**:
  - Characterization testing for unknown behavior
  - Extract and refactor for core logic
  - Rewrite for structurally broken code
  - Incremental improvement for partially modern code

- **Communicate with stakeholders**:
  - Frame modernization in business terms (revenue, velocity, risk)
  - Justify investment with quantitative data
  - Present phased plans with clear milestones

## Key Concepts

### Data-Driven Metrics

**Change Frequency:**
- How often a file changes
- Reveals maintenance burden
- High frequency = active development OR recurring problems

**Complexity:**
- Cyclomatic complexity = decision points + 1
- Thresholds: 1-10 simple, 11-20 complex, 21+ very complex
- High complexity = cognitive load, bug hiding places

**Test Coverage:**
- Percentage of code executed by tests
- Low coverage = no safety net for changes
- 0% coverage = extremely risky to modify

**Hotspot Detection:**
- Combined risk score: `(Complexity × Changes × CoverageGap) + (Bugs × 10)`
- Identifies highest-risk files
- Critical: score >= 300, High: >= 100, Moderate: >= 50

**Value-Driven Prioritization:**
- Value score: `(RiskReduction + FeatureEnablement) / Effort`
- Aligns technical work with business objectives
- Maximizes ROI of modernization investment

### Refactoring Strategies

**Characterization Tests:**
- Capture current behavior before changing code
- Safety net for refactoring
- Essential for 0% coverage code

**Extract & Refactor:**
- Break apart god classes
- Extract functions, modules, services
- Reduce complexity incrementally
- Maintain backward compatibility

**Rewrite:**
- Fresh implementation from scratch
- Appropriate when: bug ratio >60%, structural failure, cheaper than incremental
- Requires: characterization tests, feature parity verification

**Incremental Improvement:**
- Small, safe changes over time
- Add tests as you modify code
- "Boy scout rule" - leave code better than you found it

## Applying to Your Codebase

### Step 1: Gather Metrics
1. Run change frequency analysis on your git repository
2. Calculate complexity for your codebase
3. Generate test coverage reports
4. Combine into hotspot analysis

### Step 2: Map to Business Context
1. Document upcoming features (next 2-3 quarters)
2. Map features to impacted files
3. Assign business value scores
4. Calculate value/effort ratios

### Step 3: Create Roadmap
1. Identify files blocking high-value features
2. Select refactoring strategies
3. Phase work (before feature quarters)
4. Estimate effort and ROI

### Step 4: Execute and Track
1. Start with highest-value files
2. Add characterization tests first
3. Refactor or rewrite as appropriate
4. Track metrics over time (coverage, complexity, bug rate)

## Troubleshooting

### Git history script fails
```bash
# Ensure you're in the right directory
cd session-4/legacy-system

# Check if git is initialized
git status

# If not, initialize
git init
```

### Coverage analysis fails
```bash
# Ensure tests run first
cd session-4/legacy-system
npm test

# Then run coverage
npm run test:coverage

# Check that coverage/ directory was created
ls -la coverage/
```

### Missing dependencies
```bash
cd session-4/legacy-system
rm -rf node_modules
npm install
```
